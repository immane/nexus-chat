    网页客户端 UI 设计¶

    最后更新: 2026-07-09
    涵盖：桌面布局、组件架构、状态管理、移动端适配方案

    1. 入口点和外壳¶

    1.1 HTML (apps/web/index.html)¶

    <div id="root"></div>
<script type="module" src="/src/main.tsx"></script>
    • 无视口元标记 - 必须为移动设备添加：
    <meta name="viewport" content="width=device-width, initial-scale=1, viewport-fit=cover">

    1.2 应用程序外壳 (apps/web/src/components/App.tsx)¶

    {user ? <ChatRoute /> : <LoginRoute />}

    两种模式渲染：

    状态 渲染
    没有经过身份验证的用户 LoginRoute（演示/真实服务器切换）
    经过身份验证的用户 ChatRoute（完整聊天布局）

    没有路由器。没有布局包装器。整个应用程序是一个单页条件渲染。

    1.3 样式输入 (apps/web/src/styles.css)¶

    • Tailwind 指令 (@tailwind base/components/utilities)
    • 一个自定义层：.md-content 用于渲染 Markdown
    • 全局：html, body, #root { overflow: hidden; height: 100%; }

    1.4 顺风配置（apps/web/tailwind.config.ts）¶

    export default {
  content: ["./index.html", "./src/**/*.{ts,tsx}", "../../packages/ui/src/**/*.{ts,tsx}"],
  theme: { extend: {} },
  plugins: []
} satisfies Config;
    • 默认断点：sm:640px、md:768px、lg:1024px、xl:1280px
    • 没有自定义断点，没有暗模式配置
    • md:768px是移动/桌面边界

    2. Zustand 状态架构¶

    apps/web/src/stores/domain.ts 中的所有商店。

    2.1 店铺地图¶

    商店 关键国家 坚持 移动相关性
    useAuthStore user、accessToken localStorage 无
    useWorkspaceStore workspaces、activeWorkspaceId 没有 无
    useChannelStore channels、activeChannelId、unreadCounts 没有 无
    useMessageStore messages（地图）、reactions（地图）、order 没有 无
    usePresenceStore onlineUserIds（设置） 没有 无
    useSignalStore e2eEnabledChannelIds 没有 无
    useBotStore manifests、inputActions 没有 无
    useUiStore sidebarOpen、messageDraft、disappearingPolicy、settings localStorage 设置 sidebarOpen 是移动侧边栏切换

    2.2 UiStore详情¶

    interface UiState {
  sidebarOpen: boolean;           // Desktop: always true. Mobile: toggled by hamburger.
  messageDraft: string;
  disappearingPolicy: "off" | "24h" | "7d" | "30d";
  settings: {
    theme: "dark" | "light";
    compact: boolean;
    sound: boolean;
    notifications: boolean;
  };
  setSidebarOpen: (open: boolean) => void;
  setMessageDraft: (draft: string) => void;
  setDisappearingPolicy: (policy: string) => void;
  setSettings: (partial: Partial<UiSettings>) => void;
}

    sidebarOpen 当前在 UI 中未使用，但已完全定义并准备好用于移动汉堡包接线。

    5. 当前响应行为（损坏）¶

    整个代码库中仅存在 3 个响应式类：

    地点 班级 效果
    ChatRoute.tsx:508 max-md:grid-cols-1 网格变成单列
    ChatRoute.tsx:509 max-md:border-b max-md:border-r-0 侧边栏边框切换方向
    RightMemberPanel.tsx:41 max-md:hidden 右侧面板隐藏

    5.1 为什么当前行为在移动设备上被破坏¶

    1. 无 <meta name="viewport"> → 浏览器以 980px 桌面视口渲染。一切都被缩小并且无法读取。
    2. max-md:grid-cols-1 将完整的 280px 侧边栏堆叠在聊天区域上方。用户必须滚动浏览整个频道列表才能看到任何消息。
    3. 侧边栏没有关闭机制——它永久占据视口的顶部。
    4. onContextMenu（右键单击）在触摸设备上不会触发 - 消息是非交互式的。
    5. 模态和表情符号选择器使用固定宽度，在小视口上溢出。

    6. 移动适配计划¶

    移动边界：< 768px（Tailwindmax-md:断点）。

    6.1 P0 — 必备（没有这些，应用程序无法使用）¶

    6.1.1 视口元标记¶

    文件：apps/web/index.html

    <meta name="viewport" content="width=device-width, initial-scale=1, viewport-fit=cover">

    在任何其他移动修复之前需要。如果没有此选项，浏览器将呈现缩小的 980 像素桌面视图。

    6.1.2 移动侧边栏作为覆盖抽屉¶

    文件：apps/web/src/components/ChatRoute.tsx（~第 508 行）

    桌面（不变）： 侧边栏是左侧网格列（w-[280px]），始终可见。

    移动设备 (max-md:)： 侧边栏变为固定覆盖：

    ┌────────────────────────────────┐
│ ████████████ │                 │
│ █ Sidebar ██ │  Chat Area      │
│ █ 85vw    ██ │                 │
│ █         ██ │                 │
│ ████████████ │                 │
│              │                 │
│ Backdrop ░░░░│                 │
└────────────────────────────────┘

    行为： - 在移动设备上默认隐藏 (max-md:hidden) - 当 sidebarOpen === true 时，覆盖层从左侧滑入 - 侧边栏后面覆盖半透明背景；点击关闭 - 选择频道会自动关闭侧边栏 - Escape键关闭侧边栏 - 平滑的 CSS 过渡 (transition-transform duration-200)

    实施方式：

    {/* Backdrop overlay */}
{sidebarOpen && (
  <div className="max-md:fixed max-md:inset-0 max-md:z-30 max-md:bg-black/50"
       onClick={() => setSidebarOpen(false)} />
)}

{/* Sidebar */}
<aside className={
  `flex flex-col h-screen overflow-hidden border-r
   max-md:fixed max-md:inset-y-0 max-md:left-0 max-md:w-[85vw] max-md:max-w-[320px]
   max-md:z-40 max-md:shadow-2xl
   ${sidebarOpen ? 'max-md:translate-x-0' : 'max-md:-translate-x-full'}
   transition-transform duration-200`
}>

    6.2.2 长按上下文菜单¶

    文件：apps/web/src/components/MessageRow.tsx

    将仅右键单击行为替换为对触摸设备的长按支持：

    const longPressTimer = useRef<ReturnType<typeof setTimeout> | null>(null);
const longPressTriggered = useRef(false);

const onTouchStart = () => {
  longPressTriggered.current = false;
  longPressTimer.current = setTimeout(() => {
    longPressTriggered.current = true;
    // Open action sheet (same actions as right-click menu)
  }, 500);
};

const onTouchEnd = () => {
  if (longPressTimer.current) clearTimeout(longPressTimer.current);
};

const onTouchMove = () => {
  // Cancel if finger moved more than 10px
  if (longPressTimer.current) clearTimeout(longPressTimer.current);
};

    在移动设备上，将操作菜单呈现为底部工作表（全宽面板从底部向上滑动）而不是固定位置下拉菜单。操作：回复、复制、转发、编辑、删除、反应。

    6.3.5 Composer 键盘避免¶

    文件：apps/web/src/components/ChatComposer.tsx

    作曲家位于 Flex 布局的底部，在大多数浏览器上会被虚拟键盘向上推。对于带有 visualViewport 的 iOS Safari，可能需要额外的处理：

    useEffect(() => {
  const handler = () => {
    const viewport = window.visualViewport;
    if (viewport) {
      document.documentElement.style.setProperty(
        '--viewport-offset',
        `${window.innerHeight - viewport.height}px`
      );
    }
  };
  window.visualViewport?.addEventListener('resize', handler);
  return () => window.visualViewport?.removeEventListener('resize', handler);
}, []);

    注意：这是P2。大多数移动浏览器都可以在没有明确干预的情况下处理这个问题。

    8. 设计决策¶

    8.1 为什么覆盖抽屉，而不是汉堡替换¶

    在移动设备上，用当前的 max-md:grid-cols-1 方法替换内联侧边栏内容（聊天上方）是不可用的：

    • 侧边栏85%是频道导航，这不是移动设备上的即时任务
    • 用户打开应用程序阅读和发送消息；频道切换是次要的
    • 覆盖抽屉提供相同的导航功能，而无需牺牲消息的屏幕空间

    8.2 为什么长按而不是点击选择¶

    桌面使用右键单击进行上下文操作。手机没有右键。替代方案：

    方法 专业 骗局
    点击选择然后操作栏 可发现 额外的步骤；打破现有的肌肉记忆
    滑动操作（左/右） 常见于聊天应用 在虚拟化列表上实现复杂
    长按→底页 符合 iOS/Android 惯例 需要 500 毫秒延迟

    长按是移动消息应用程序最自然的选择。

    8.3 为什么要设置md:768px断点¶

    Tailwind 在 768px 处的默认 md 断点是标准平板电脑/移动设备边界。大多数平板电脑的横向尺寸都≥768px，并且可以使用桌面布局。纵向手机<768px并获得移动布局。

    8.4 为什么没有自定义断点¶

    默认的 Tailwind 断点就足够了： - md:768px 涵盖所有手机（纵向）和大多数小型平板电脑 - 桌面布局从 768px 向上工作 - 不需要自定义 mobile 断点，例如 480px

    9. URL/路由¶

    不使用客户端路由器。整个应用程序位于一个 URL 上。状态转换由以下因素驱动：

    • useAuthStore.user — 在 LoginRoute 和 ChatRoute 之间切换
    • useChannelStore.activeChannelId — 在“欢迎”视图和“消息”视图之间切换
    • useUiStore.sidebarOpen — 切换侧边栏可见性（移动设备）
    • rightSidebarOpen（ChatRoute 中的本地状态）- 切换右侧成员面板

    10. 主题¶

    通过 useUiStore.settings.theme 支持两个主题：

    主题 背景 文字
    深色（默认） bg-slate-950 / bg-slate-900 text-slate-100
    光 bg-white / bg-slate-50 text-slate-900

    主题保留在 localStorage 中，并通过 Tailwind 类切换应用。
