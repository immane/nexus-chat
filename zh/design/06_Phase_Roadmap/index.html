    06 — 阶段路线图和里程碑计划¶

    Nexus-chat · 类似 Slack 的 IM 应用
    设计日期：2026 年 6 月 · 状态：Draft v1.1（更新于 2026-07-10）
    目标：SaaS多租户云部署

    目录¶

    1.Overview & Timeline 2. Phase 1 — MVP Foundation (0–3 months) 3.Phase 2 — Rich Features & Production Hardening (+3–6 months) 4. Phase 3 — Advanced & Enterprise (+6–12 months) 5.Infrastructure Evolution 6. Bot Catalog Rollout 7.AI Agent Implementation Sequence 8. Package Delivery Matrix

    1. 概述和时间表¶

    Phase 1 (MVP)           Phase 2 (Production)        Phase 3 (Enterprise)
├───────────────────────┼───────────────────────────┼───────────────────────→
Month 0            Month 3                    Month 6                Month 12
    相 持续时间 目标 发射准备
    第一阶段 0-3 个月 具有混合加密功能的类似 Slack 的可用 IM 内部 alpha、内测
    第二阶段 第 3-6 个月 功能齐全的 IM 平台已准备好公开发布 公开 GA 发布
    第三阶段 6-12 个月 具有先进人工智能和生态系统的企业级平台 企业计划

    1.1 可行性护栏¶

    该路线图有意雄心勃勃，但实施应保持里程碑式的控制。核心原则是： 首先交付一个狭窄的、可靠的 IM 核心；将可选的产品表面区域移至机器人中；推迟复杂的基础设施，直到底层原语稳定为止。

    轨道 必须在测试版之前发货 拉伸/可滑动
    第一阶段核心 身份验证、工作区、通道、正常模式短信、基本桌面 shell、TUI 烟雾客户端、WebSocket 网关 完整的 Electron 抛光，所有 7 个基础机器人，自动更新抛光
    第一阶段机器人基础设施 机器人注册、令牌验证、命令调用、一个参考机器人 完整的第一方机器人目录
    第二阶段核心 附件服务、全文搜索、话题、存在/已读收据、打包 如果信号发送器密钥复杂性延迟，则 E2E 组将启动
    第二阶段人工智能 流协议、/ai ask/summarize/translate/draft、全文检索工具 pgvector RAG，自主回顾，高级工具
    第三阶段 企业/市场/微服务工作分成独立的轨道 任何物品都可以独立运送，而不会阻塞其余物品

    这个护栏使第一阶段对于小团队来说是可行的，并防止第二阶段成为一个单一的超大发布列车。

    2. 第 1 阶段 — MVP 基础（0-3 个月）¶

    2.1 核心目标¶

    提供类似 Slack 的工作 IM，展示关键区别：每通道混合加密（正常 = IM + Bot，E2E = 仅 IM）。

    2.2 功能交付成果¶

    特色专区 可交付成果 参考设计
    项目脚手架 pnpm monorepo + Turborepo、TypeScript 严格模式、ESLint + Prettier、Vitest、CI/CD 管道 —
    授权 电子邮件/密码注册 + 登录、JWT（访问 15 分钟 + 刷新 7 天）、Argon2id 密码哈希、令牌轮换、会话管理 03 - Business Logic
    工作区 创建/加入工作区、工作区设置、成员邀请、角​​色管理（所有者/管理员/成员） 03 - Business Logic
    频道 公共/私人频道、DM 对话、频道创建、存档、会员管理、每频道模式切换（正常/e2e） 03 - Business Logic
    消息 短信、消息状态机（草稿 → 发送 → 已发送 → 已发送 → 已读）、基于光标的分页 (UUID v7)、编辑/删除（软）、表情符号反应 03 - Business Logic
    内容丰富 Markdown 渲染（markdown-it + Shiki 代码）、表情符号选择器 (emoji-mart)、@mention 自动完成 01 - Client Shell
    DM E2E ECDH + AES-256-GCM（第 1-2 阶段，MIT 兼容，主分支）。采用 X3DH + 双棘轮的信号协议计划在单独的分发分支上进行第 3 阶段（不在 main 中），以避免来自 @signalapp/libsignal 的 AGPL-3.0 许可证污染。 10 - E2EE Encryption Abstract Layer
    端到端消失的消息 1:1 E2E DM 的一次读取和基于计时器的过期策略；服务器仅存储策略元数据、密文、逻辑删除状态和到期时间戳 03 - Business Logic
    机器人（基本） Bot 注册 + 令牌发行 (nxbot_v1_xxx)、/slash 命令解析 + 路由、Bot WebSocket 连接生命周期、Redis Streams 事件总线 04 - Bot Engine
    网关 Hono HTTP 服务器 + Socket.IO WebSocket、JWT 身份验证中间件、速率限制（滑动窗口）、CORS/Helmet.js/CSP、Zod 验证、心跳（30s） 02 - Gateway
    用户界面外壳 单窗口 Electron 布局（侧边栏 + 聊天视图 + 详细信息面板）、Zustand 商店（auth/workspace/channel/message/presence/signal/ui）、react-virtuoso 消息列表、深色/浅色主题、Tailwind CSS v4 01 - Client Shell
    桌面外壳 Electron 窗口管理、系统托盘、本机通知、自动更新（电子更新程序）、contextBridge IPC 01 - Client Shell
    途易客户端 Ink + Commander 终端客户端用于登录、工作区/频道导航、正常消息传递、E2E DM 冒烟测试和机器人命令冒烟测试 01 - Client Shell
    基础设施 整体部署（Hono + Socket.IO + Bot Engine 在一个进程中）、PostgreSQL 16、Redis 7、Pino 结构化日志记录、dotenv 配置 00 - System Architecture
