    Nexus Chat 桌面应用程序 shell (Electron)、第一阶段终端 UI 客户端和基于 React 的 UI 渲染层的设计文档。 涵盖流程架构、组件树、状态管理、交互流程和性能策略。
    源自Frontend Architecture Research。

    1.电子壳架构¶

    1.1 流程模型¶

    该应用程序遵循 Electron 的标准多进程模型，具有严格的安全边界：

    ┌──────────────────────────────────────────────────────────────┐
│  Main Process (Node.js)                                       │
│  ├── main.ts              Entry point, app lifecycle          │
│  ├── window-manager.ts    BrowserWindow creation & lifecycle  │
│  ├── tray.ts              System tray icon & context menu     │
│  ├── updater.ts           electron-updater integration        │
│  ├── notifications.ts     Native notification dispatch        │
│  ├── network-monitor.ts   Connectivity detection              │
│  └── ipc/
│      └── handlers.ts      IPC handler registration            │
├──────────────────────────────────────────────────────────────┤
│  Preload Script (contextBridge)                               │
│  └── preload.ts           Typed API exposed to renderer       │
├──────────────────────────────────────────────────────────────┤
│  Renderer Process (Chromium sandbox)                          │
│  ├── apps/web/            Vite-built React SPA                │
│  └── window.electronAPI   Type-safe IPC consumer              │
└──────────────────────────────────────────────────────────────┘

    安全限制： - contextIsolation: true — 渲染器无法直接访问 Node.js API。 - sandbox: true — 渲染器在操作系统级沙箱中运行。 - 所有主要流程功能均通过 contextBridge.exposeInMainWorld 通过预加载脚本进行控制。

    1.2 主要流程职责¶

    窗口管理¶

    WindowManager 类拥有所有 BrowserWindow 实例的生命周期：

    // electron/window-manager.ts
class WindowManager {
  private mainWindow: BrowserWindow | null = null
  private popupWindows = new Map<string, BrowserWindow>()

  createMainWindow(): BrowserWindow {
    this.mainWindow = new BrowserWindow({
      width: 1200,
      height: 800,
      minWidth: 800,
      minHeight: 600,
      titleBarStyle: 'hiddenInset',            // macOS native title bar
      webPreferences: {
        preload: join(__dirname, 'preload.mjs'),
        contextIsolation: true,
        sandbox: true,
      },
    })

    if (import.meta.env.DEV) {
      this.mainWindow.loadURL('http://localhost:5173')
    } else {
      this.mainWindow.loadFile(join(__dirname, '../renderer/index.html'))
    }

    return this.mainWindow
  }

  openPopup(id: string, url: string, opts?: Partial<BrowserWindowConstructorOptions>): BrowserWindow {
    const existing = this.popupWindows.get(id)
    if (existing && !existing.isDestroyed()) {
      existing.focus()
      return existing
    }
    const win = new BrowserWindow({
      width: 400,
      height: 600,
      parent: this.mainWindow!,
      ...opts,
      webPreferences: {
        preload: join(__dirname, 'preload.mjs'),
        contextIsolation: true,
        sandbox: true,
      },
    })
    win.loadURL(url)
    win.on('closed', () => this.popupWindows.delete(id))
    this.popupWindows.set(id, win)
    return win
  }
}

    系统托盘¶

    托盘图标提供快速访问以显示/隐藏主窗口和退出应用程序：

    // electron/tray.ts
export function createTray(mainWindow: BrowserWindow): Tray {
  const icon = nativeImage.createFromPath(join(__dirname, '../assets/tray-icon.png'))
  const tray = new Tray(icon.resize({ width: 16, height: 16 }))

  const contextMenu = Menu.buildFromTemplate([
    { label: 'Show/Hide', click: () =>
        mainWindow.isVisible() ? mainWindow.hide() : mainWindow.show() },
    { type: 'separator' },
    { label: 'Quit', click: () => app.quit() },
  ])

  tray.setToolTip('Nexus Chat')
  tray.setContextMenu(contextMenu)
  tray.on('click', () => mainWindow.show())
  return tray
}

    原生通知¶

    窗口未聚焦时到达的消息会生成操作系统级别的通知：

    // electron/notifications.ts
export function showNotification(
  title: string,
  body: string,
  onClick?: () => void,
): void {
  if (!Notification.isSupported()) return

  const notification = new Notification({ title, body, silent: false })
  if (onClick) {
    notification.on('click', onClick)
  }
  notification.show()
}

    徽章策略： - macOS：app.dock.setBadge(unreadCount > 0 ? String(unreadCount) : '') - Windows：mainWindow.setOverlayIcon(icon, 'Unread messages')

    自动更新程序（电子更新程序）¶

    更新程序采用用户同意的工作流程：自动检查、根据用户请求下载、退出时安装。

    // electron/updater.ts
export function setupAutoUpdater(mainWindow: BrowserWindow): void {
  autoUpdater.autoDownload = false
  autoUpdater.autoInstallOnAppQuit = true

  autoUpdater.on('update-available', (info) => {
    mainWindow.webContents.send('update:available', {
      version: info.version,
      releaseDate: info.releaseDate,
    })
  })

  autoUpdater.on('download-progress', (progress) => {
    mainWindow.webContents.send('update:progress', progress.percent)
  })

  autoUpdater.on('update-downloaded', () => {
    mainWindow.webContents.send('update:ready')
  })

  // Check every 4 hours
  setInterval(() => autoUpdater.checkForUpdates(), 4 * 60 * 60 * 1000)
  autoUpdater.checkForUpdates()
}

    1.3 预加载脚本和IPC桥¶

    预加载脚本通过 contextBridge 公开严格类型化的 API 表面：

    // electron/preload.ts
import { contextBridge, ipcRenderer } from 'electron'

const electronAPI = {
  // ── Window controls ──────────────────────────────────
  minimize:    () => ipcRenderer.invoke('window:minimize'),
  maximize:    () => ipcRenderer.invoke('window:maximize'),
  close:       () => ipcRenderer.invoke('window:close'),

  // ── File dialog ──────────────────────────────────────
  openFileDialog: (opts?: OpenDialogOptions) =>
    ipcRenderer.invoke('dialog:open-file', opts),

  // ── Notifications ────────────────────────────────────
  onNotification: (callback: (data: NotificationData) => void) => {
    const handler = (_event: IpcRendererEvent, data: NotificationData) => callback(data)
    ipcRenderer.on('notification:new', handler)
    return () => ipcRenderer.removeListener('notification:new', handler)
  },

  // ── Clipboard ────────────────────────────────────────
  writeClipboard: (text: string) => ipcRenderer.invoke('clipboard:write', text),
  readClipboard:  () => ipcRenderer.invoke('clipboard:read'),

  // ── App metadata ─────────────────────────────────────
  getAppVersion:   () => ipcRenderer.invoke('app:version'),
  checkForUpdate:  () => ipcRenderer.invoke('app:check-update'),
  downloadUpdate:  () => ipcRenderer.invoke('app:download-update'),
  installUpdate:   () => ipcRenderer.invoke('app:install-update'),

  // ── Network events (main → renderer) ─────────────────
  onNetworkStatusChange: (callback: (status: { online: boolean }) => void) => {
    const handler = (_e: IpcRendererEvent, status: { online: boolean }) => callback(status)
    ipcRenderer.on('network:status-change', handler)
    return () => ipcRenderer.removeListener('network:status-change', handler)
  },
} as const

contextBridge.exposeInMainWorld('electronAPI', electronAPI)

    渲染器进程的类型声明：

    // src/types/electron.d.ts
import type { electronAPI } from '../../electron/preload'

declare global {
  interface Window {
    electronAPI: typeof electronAPI
  }
}

    IPC设计规则：

    规则 理由
    频道命名：namespace:action 可预测的、grep 友好的
    更喜欢 invoke/handle （基于 Promise） 非阻塞；避免 sendSync
    通过 webContents.send 的单向事件 对于主→渲染器推送（例如通知、更新进度）
    每个 on 监听器都会返回一个清理函数 防止组件卸载时内存泄漏

    1.4 渲染器流程¶

    渲染器从apps/web加载Vite构建的React应用程序。在开发中，它连接到 Vite 开发服务器 localhost:5173。在生产中，它加载捆绑到 Electron 应用程序中的静态文件。

    React 应用程序拥有所有 UI 渲染、路由和客户端状态。它仅通过window.electronAPI与主进程通信。

    1.5 Vite 插件 Electron 集成¶

    该项目使用 vite-plugin- Electron v1.0.4 和 simple API 进行零配置启动：

    // vite.config.ts (simplified)
import electron from 'vite-plugin-electron'
import renderer from 'vite-plugin-electron-renderer'

export default defineConfig({
  plugins: [
    electron([
      {
        entry: 'electron/main.ts',
        vite: {
          build: {
            outDir: 'dist-electron',
            rollupOptions: {
              external: ['electron', 'electron-updater', 'electron-store'],
            },
          },
        },
      },
      {
        entry: 'electron/preload.ts',
        onstart(args) {
          args.reload()
        },
        vite: {
          build: {
            outDir: 'dist-electron',
          },
        },
      },
    ]),
    renderer(),
  ],
})

    该插件提供的主要功能： - 开发过程中源代码更改时主进程的热重启。 - 自动 ESM 兼容性垫片 (__dirname / __filename)。 - notBundle 插件，用于在开发过程中外部化依赖项以加速重建。

    1.6 多窗口策略¶

    Nexus Chat采用单一主窗口+按需弹出窗口的模式：

    窗口 触发 行为
    主聊天窗口 应用程序启动 托管完整 React SPA 的单个 BrowserWindow；所有工作区/通道切换都通过 React Router 在窗口内进行
    设置弹出窗口 用户打开“设置” 独立的 BrowserWindow (400×600)，父窗口为主窗口；加载专用路线
    视频/语音通话（未来） 用户发起呼叫 分离弹出窗口，以便在导航主窗口时调用仍然存在

    理由： - 单一主窗口避免了跨窗口状态同步的复杂性。 - 辅助工作流程（设置、通话）的弹出窗口可防止它们干扰主聊天视图。 - 所有窗口共享相同的预加载脚本，因此 IPC API 是统一的。

    2. React 应用程序结构¶

    2.1 入口点层次结构¶

    main.tsx          →  ReactDOM.createRoot, providers, global styles
  └── App.tsx      →  Router, layout shell, top-level error boundary
        └── Router  →  Route definitions (React Router v7)
              └── Pages  →  AuthPage | ChatPage | SettingsPage

    main.tsx 职责： - 将 React 树挂载到 #root 中。 - 用 <ThemeProvider> 包裹（在 <html> 上应用深色/浅色类别）。 - 用 <QueryClientProvider> 包裹（服务器数据的 TanStack 查询，如果使用）。 - 导入全局 CSS (styles/theme.css)。

    App.tsx 职责： - 使用路由表实例化 React Router。 - 渲染顶级<ErrorBoundary>。 - 可以选择在安装时初始化 WebSocket 连接。

    2.2 路由表¶

    路径 页面组件 描述
    /auth/login AuthPage（登录表单） 邮箱/密码登录
    /auth/register AuthPage（注册表格） 帐户创建
    /chat/:workspaceId/:channelId? ChatPage 主聊天界面；用于深度链接的可选 channelId
    /settings SettingsPage 应用程序设置

    代码结构：

    // src/router.tsx
const ChatPage = lazy(() => import('@/pages/chat'))
const AuthPage = lazy(() => import('@/pages/auth'))
const SettingsPage = lazy(() => import('@/pages/settings'))

export function AppRouter() {
  return (
    <Suspense fallback={<FullScreenSpinner />}>
      <Routes>
        <Route path="/auth/login" element={<AuthPage mode="login" />} />
        <Route path="/auth/register" element={<AuthPage mode="register" />} />
        <Route path="/chat/:workspaceId/:channelId?" element={<ChatPage />} />
        <Route path="/settings" element={<SettingsPage />} />
        <Route path="*" element={<Navigate to="/auth/login" replace />} />
      </Routes>
    </Suspense>
  )
}

    2.3 布局组件¶

    主要布局 shell 是 WorkspaceLayout，在 ChatPage 中处于活动状态：

    ┌─────────────────────────────────────────────────────────┐
│ WorkspaceLayout                                          │
│ ┌───────────┬──────────────────────┬──────────────────┐ │
│ │           │                      │                  │ │
│ │  Sidebar  │     Main Panel       │   Detail Panel   │ │
│ │  (260px)  │     (flex-1)         │   (320px, cond)  │ │
│ │           │                      │                  │ │
│ └───────────┴──────────────────────┴──────────────────┘ │
└─────────────────────────────────────────────────────────┘
    • 侧边栏 (WorkspaceSidebar)：固定 260px。包含工作区切换器和频道列表。
    • 主面板：弹性增长以填充剩余空间。包含通道头、消息列表和消息输入。
    • 细节面板：有条件渲染（320px）。触发频道标头操作时显示频道信息或成员列表。

    DetailPanel 通过 uiStore.detailPanel 切换，避免单独的路由并保留消息列表中的滚动位置。

    2.4 代码分割策略¶

    所有页面级组件均通过 React.lazy + <Suspense> 加载：

    const ChatPage     = lazy(() => import('@/pages/chat'))
const AuthPage     = lazy(() => import('@/pages/auth'))
const SettingsPage = lazy(() => import('@/pages/settings'))

    此外，重型交互式小部件在组件级别上进行了拆分： - EmojiPicker — 延迟加载表情符号按钮的第一个焦点。 - FilePreview（图像/视频查看器）- 文件单击时延迟加载。 - CommandPalette (Cmd+K) — 在第一次键盘调用时延迟加载。

    这可确保身份验证页面的初始捆绑包最小化（gzip 后 <100 KB），并且聊天页面的关键路径（消息列表 + 输入）无需等待辅助组件即可加载。

    3. Zustand状态管理架构¶

    3.1 店铺细分¶

    每个商店都是一个独立的 Zustand create 调用，按域划分：

    authStore¶

    领域/行动 类型 描述
    accessToken string \| null JWT 访问令牌
    refreshToken string \| null JWT 刷新令牌
    user User \| null 当前用户个人资料（id、displayName、avatarUrl）
    isAuthenticated boolean 派生：accessToken !== null
    login(email, password) async () => void 身份验证、存储令牌
    logout() () => void 清除令牌，断开 WS，导航到 /auth/login
    refreshSession() async () => void 通过refreshToken进行静默令牌刷新

    令牌持久保存在 electron-store （加密、钥匙串支持）中，而不是 Zustand 持久中间件中，因为令牌是安全敏感的。

    workspaceStore¶

    领域/行动 类型 描述
    workspaces Workspace[] 用户所属的所有工作区
    currentWorkspaceId string \| null 当前活动工作区
    members Record<string, Member[]> 由workspaceId 键入的成员
    setWorkspaces(ws) (ws: Workspace[]) => void 设置工作区列表
    switchWorkspace(id) (id: string) => void 切换活动工作区

    channelStore¶

    领域/行动 类型 描述
    channels Map<string, Channel> 由 id 键控的通道实体
    currentChannelId string \| null 当前观看的频道
    unreadCounts Record<string, number> 每个频道的未读计数
    e2eFlags Record<string, boolean> 通道是否建立端到端会话
    switchChannel(id) (id: string) => void 切换活动频道，清除未读
    incrementUnread(channelId) (id: string) => void 增加未读邮件数量

    messageStore¶

    使用带有 Map 的标准化存储进行 O(1) 查找和单独的排序数组：

    interface MessageStoreState {
  messageMap:    Map<string, Message>        // id → Message
  channelOrder:  Record<string, string[]>    // channelId → [messageId, ...]
  cursors:       Record<string, { oldest?: string; newest?: string; hasMore: boolean }>

  upsertMessages:  (channelId: string, msgs: Message[]) => void
  loadOlderMessages: (channelId: string, beforeId: string) => Promise<void>
  appendNewMessage: (channelId: string, msg: Message) => void
  updateMessageStatus: (tempId: string, serverId: string, status: MessageStatus) => void
}

    关键设计决策： - 地图 + 顺序数组（标准化）：通过 id 查找 O(1)，通过 ID 列表有序渲染。 - 基于光标的分页：cursors[channelId] 跟踪最旧/最新加载的消息 ID 以及是否存在更多消息。 - upsert 上的重复数据删除：如果映射中已存在消息 ID，则合并字段（用于状态更新、编辑）；否则按时间戳顺序插入。

    渲染选择器（从标准化存储中导出数组）：

    const selectMessages = (channelId: string) => (state: MessageStoreState): Message[] => {
  const order = state.channelOrder[channelId]
  if (!order) return []
  return order.map(id => state.messageMap.get(id)!).filter(Boolean)
}

    3.3 WebSocket 中间件模式¶

    WebSocket 连接通过 Zustand 中间件进行管理，该中间件封装了生命周期（连接、以指数退避重新连接、断开连接）：

    // stores/ws-middleware.ts
export function websocketMiddleware<State extends { ws: WebSocket | null }>(
  url: string,
  onMessage: (event: MessageEvent, set: any, get: any) => void,
): StateCreator<State & WSActions> {
  let socket: WebSocket | null = null
  let reconnectTimer: ReturnType<typeof setTimeout> | null = null
  let attempts = 0

  return (set, get, api) => ({
    ...api,
    ws: null,

    wsConnect: () => {
      if (socket?.readyState === WebSocket.OPEN) return

      socket = new WebSocket(url)

      socket.onopen = () => {
        set({ ws: socket } as any)
        attempts = 0
      }

      socket.onmessage = (event) => onMessage(event, set, get)

      socket.onclose = () => {
        set({ ws: null } as any)
        const delay = Math.min(1000 * 2 ** attempts, 30000)
        attempts++
        reconnectTimer = setTimeout(() => {
          (get as any)().wsConnect()
        }, delay)
      }
    },

    wsDisconnect: () => {
      if (reconnectTimer) clearTimeout(reconnectTimer)
      socket?.close()
      socket = null
      attempts = 0
      set({ ws: null } as any)
    },

    wsSend: (event, payload) => {
      socket?.send(JSON.stringify({ event, payload }))
    },
  })
}

    onMessage 回调根据 WebSocket 事件类型分派到适当的存储：

    ws message → { event: "message:new", payload: {...} }
  ├── "message:new"        → messageStore.upsertMessages
  ├── "message:ack"        → messageStore.updateMessageStatus
  ├── "presence:update"    → presenceStore.setUserOnline
  ├── "typing:start"       → presenceStore.setTyping
  ├── "channel:created"    → channelStore.addChannel
  └── "signal:prekey"      → signalStore.fetchPreKeyBundle → initiateSession

    5. 关键交互流程¶

    5.1 发送消息¶

    User types text + Enter
        │
        ▼
MessageInput.onSubmit(text)
        │
        ├── 1. Generate tempId (crypto.randomUUID())
        ├── 2. Create optimistic Message {id: tempId, status: 'sending'}
        │      └── messageStore.upsertMessages(channelId, [optimisticMsg])
        │           └── React re-renders MessageList with new bubble (status icon: clock)
        │
        ├── 3. Network check
        │      ├── Online  → wsSend('message:send', {tempId, channelId, text})
        │      └── Offline → offlineQueueStore.enqueue({tempId, channelId, text})
        │
        ▼
Server receives → validates → persists → broadcasts to channel members
        │
        ▼
Server → Client ACK: {event: "message:ack", tempId, serverId, timestamp}
        │
        ▼
messageStore.updateMessageStatus(tempId, serverId, 'sent')
        └── React re-renders: clock icon → check icon, tempId → serverId

    5.2 接收消息¶

    WebSocket push: {event: "message:new", payload: {id, channelId, senderId, text, timestamp, ciphertext?}}
        │
        ├── 1. If ciphertext present → signalStore.decrypt(channelId, ciphertext) → plaintext
        │
        ├── 2. messageStore.upsertMessages(channelId, [message])
        │      └── Deduplication check: if id already in messageMap, skip or merge
        │      └── Insert in timestamp order into channelOrder
        │
        ├── 3. If channelId !== currentChannelId → channelStore.incrementUnread(channelId)
        │
        ├── 4. If window not focused → main process showNotification(title, body)
        │      └── Notification click → window.focus() + navigate to channel
        │
        └── 5. React re-renders MessageList (Virtuoso followOutput scrolls to bottom)

    5.3 第一个 DM 上的 E2E 密钥交换¶

    User opens DM with peer for the first time
        │
        ▼
signalStore.encryptionReady[channelId] === false
        │
        ▼
E2EBanner displayed: "End-to-end encryption is being set up..."
        │
        ├── 1. signalStore.fetchPreKeyBundle(peerUserId)
        │      └── GET /api/users/:peerUserId/prekey-bundle
        │      └── Store in signalStore.preKeyBundles.set(peerUserId, bundle)
        │
        ├── 2. signalStore.initiateSession(channelId, peerUserId)
        │      ├── X3DH key agreement using local identity key + peer's PreKeyBundle
        │      ├── Establish SessionRecord
        │      └── signalStore.sessions.set(`${channelId}:${peerUserId}`, session)
        │
        ├── 3. signalStore.encryptionReady[channelId] = true
        │
        └── E2EBanner dismisses; all subsequent messages encrypted via Signal session

    6.6 长消息列表的内存控制¶

    Zustand 仅在内存中保留最后 每个通道 200 条消息；较旧的消息存在于 IndexedDB 中：

    const MEMORY_WINDOW = 200

function trimMessageMemory(channelId: string): void {
  const { channelOrder, messageMap } = useMessageStore.getState()
  const ids = channelOrder[channelId] ?? []

  if (ids.length <= MEMORY_WINDOW) return

  const toRemove = ids.slice(0, ids.length - MEMORY_WINDOW)
  const newMap = new Map(messageMap)
  for (const id of toRemove) newMap.delete(id)

  useMessageStore.setState({
    messageMap: newMap,
    channelOrder: {
      ...channelOrder,
      [channelId]: ids.slice(ids.length - MEMORY_WINDOW),
    },
  })
}

    trimMessageMemory 在 loadOlderMessages 完成后且当用户切换频道时调用。

    // hooks/use-theme.ts
export function useTheme() {
  const theme = useUIStore(s => s.theme)
  const setTheme = useUIStore(s => s.setTheme)

  useEffect(() => {
    const root = document.documentElement

    if (theme === 'system') {
      const mq = window.matchMedia('(prefers-color-scheme: dark)')
      root.classList.toggle('dark', mq.matches)
      const handler = (e: MediaQueryListEvent) => root.classList.toggle('dark', e.matches)

    }

    root.classList.toggle('dark', theme === 'dark')
  }, [theme])

  return { theme, setTheme }
}

    端到端 通过packages/signal建立1:1 DM会话；发送/读取加密和一次读取的消息
    机器人 在正常渠道中调用斜杠命令并呈现机器人回复
    CI烟 具有确定性退出代码的非交互式 send、read、e2e-smoke 和 bot-smoke 命令

    8.2 边界¶

    • TUI 必须从 packages/shared 导入模式和事件名称；没有重复的 API 类型。
    • TUI必须使用packages/signal进行加密和解密；没有单独的加密实现。
    • 本地令牌存储应优先选择操作系统钥匙串（如果可用）。 .env 或明文回退仅允许用于本地开发和 CI。
    • TUI 不是特定于功能的管理工具。除非明确提升到后续阶段，否则管理和事件响应命令将被推迟。
