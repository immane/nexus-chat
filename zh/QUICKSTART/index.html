    Nexus 聊天快速入门¶

    中文快速开始 | Full README

    本指南获取运行本地第一阶段 Nexus Chat 工作区以进行开发和冒烟测试。

    1.先决条件¶

    首先安装这些：

    • Node.js 22 或更高版本。 -pnpm 9.15.x。
    • Docker 桌面或 Docker 引擎。

    检查版本：

    node --version
pnpm --version
docker --version

    2.安装依赖项¶

    pnpm install

    3.创建本地环境文件¶

    cp .env.example .env

    默认值适合本地开发：

    HOST=127.0.0.1
PORT=4000
WEB_ORIGIN=http://localhost
DATABASE_URL=postgres://nexus:nexus@localhost:5432/nexus_chat
REDIS_URL=redis://localhost:6379
SESSION_STORE=memory
API_PUBLIC_BASE=http://127.0.0.1:4000
VITE_API_BASE=http://127.0.0.1:4000

    如果您希望在本地测试期间刷新存储在 Redis 中的会话，请使用 SESSION_STORE=redis。

    4.启动本地服务器容器¶

    docker compose build server
docker compose up -d

    确认服务器正在运行：

    docker compose ps
curl http://127.0.0.1:4000/healthz

    第 1 阶段运行时服务使用内存域存储。 PostgreSQL 和 Redis 在 docker-compose.yml 中被有意注释掉，直到连接持久性为止。

    要使用 Docker 运行服务器和 Web：

    docker compose up -d --build server web

    Web 容器在 http://127.0.0.1:5173 上为构建的应用程序提供服务。 VITE_API_BASE 在构建时烘焙到 Web 映像中。对于 LAN 访问，请使用主机 API URL 进行重建：

    VITE_API_BASE=http://192.168.1.20:4000 docker compose up -d --build web

    5. 内存中的开发数据种子¶

    bash scripts/dev-bootstrap.sh

    开发凭据：

    电子邮件 密码
    alice@dev.local test1234abcd
    bob@dev.local test1234abcd

    引导程序创建 Dev Workspace、默认 #general 通道以及 Bob 的工作区/通道成员身份。重新启动或重建服务器容器后重新运行它，因为存储位于内存中。

    6. 启动开发服务器¶

    对于 Docker 服务器加 Web UI 流程，保持服务器容器运行并单独启动 Vite：

    pnpm --filter @nexus-chat/web dev

    对于原生全应用开发流程，如果 Docker 拥有端口 4000，请先停止 Docker，然后运行：

    docker compose down
pnpm dev

    打开：

    • Web客户端：Web开发服务器打印的Vite URL，通常为http://localhost:5173或http://localhost:5174
    • API健康检查：http://127.0.0.1:4000/healthz
    • 指标：http://127.0.0.1:4000/metrics

    Web应用程序支持演示模式和真实服务器模式。在实服务器模式下，使用上面的开发凭据或通过 API/UI 注册另一个用户。

    对于 LAN 或主机访问，请一致使用主机 IP：

    HOST=0.0.0.0
WEB_ORIGIN=http://192.168.1.20:5173
VITE_API_BASE=http://192.168.1.20:4000
API_PUBLIC_BASE=http://192.168.1.20:4000

    将 192.168.1.20 替换为您的主机 IP 或域。 TUI 客户端可以使用 NEXUS_API_BASE=http://192.168.1.20:4000；桌面版本使用与 Web 客户端相同的 VITE_API_BASE 值。

    7. 运行快速验证通行证¶

    在单独的外壳中：

    pnpm lint
pnpm typecheck
pnpm test
pnpm coverage

    预期结果：所有命令通过。目前的报表覆盖率超过 99%，分支覆盖率超过 90%。

    8. 尝试 TUI/CLI¶

    显示帮助：

    pnpm --filter @nexus-chat/tui dev --help

    登录本地服务器：

    pnpm --filter @nexus-chat/tui dev login -e alice@dev.local -p test1234abcd

    列出工作区：

    pnpm --filter @nexus-chat/tui dev workspaces

    运行冒烟测试：

    pnpm --filter @nexus-chat/tui dev api-smoke
pnpm --filter @nexus-chat/tui dev p2p-smoke
pnpm --filter @nexus-chat/tui dev bot-smoke
pnpm --filter @nexus-chat/tui dev e2e-smoke

    运行完整的原生 CI 烟雾流：

    docker compose down
pnpm smoke:tui:ci

    smoke:tui:ci 在端口 4000 上启动自己的本机服务器，因此 Docker 不得已绑定到该端口。

    CLI 将其本地令牌存储在 .env.tui 中，Git 会忽略该令牌。

    9. 运行单独的应用程序¶

    仅服务器：

    pnpm --filter @nexus-chat/server dev

    仅限网络：

    pnpm --filter @nexus-chat/web dev

    桌面外壳：

    pnpm --filter @nexus-chat/desktop dev

    TUI/CLI：

    pnpm --filter @nexus-chat/tui dev --help

    10. 有用的重置命令¶

    停止基础设施：

    docker compose down

    重新创建内存中的 Docker 服务器和种子数据：

    docker compose down
docker compose build server
docker compose up -d
bash scripts/dev-bootstrap.sh

    清除 TUI 身份验证令牌：

    pnpm --filter @nexus-chat/tui dev logout

    故障排除¶

    如果 pnpm dev 或 smoke:tui:ci 无法绑定到端口，请检查使用端口 4000、5173 或 5174 的现有进程。在运行本机 CI 烟雾之前使用 docker compose down 停止 Docker。

    如果在 TUI 中登录失败，请确认服务器正在运行并且运行时具有预期的用户。由于第一阶段运行时服务默认使用内存存储，因此您需要在每个新服务器启动后运行 scripts/dev-bootstrap.sh 或手动注册用户。

    如果 pnpm db:migrate 失败，请记住默认 Docker 流不会启动 PostgreSQL。如果要验证迁移，请先取消 docker-compose.yml 中 PostgreSQL 的注释。

    如果 WebSocket 命令失败，请确认可以通过 VITE_API_BASE 访问服务器。本地客户端默认为 127.0.0.1 以避免 IPv4/IPv6 本地主机歧义。对于浏览器客户端，将 WEB_ORIGIN 设置为实际的 Web 源，例如 http://localhost、http://127.0.0.1 或 http://192.168.x.x:5173。

    仅对于临时本地/LAN 测试，设置 WEB_ORIGIN=* 以禁用 CORS/WebSocket 源过滤。不要将其用于公共部署。
