    Nexus Chat — 文档中心¶

    类似 Slack 的即时消息平台，具有混合加密模式 - [正常] IM + Bot，或仅 [端到端加密] IM - 作为 SaaS 多租户 Electron 桌面应用程序提供。

    1. 项目概要¶

    Nexus Chat 是一个桌面优先的团队通信平台，它将熟悉的 Slack 风格消息传递与现代加密保证相结合。每个渠道和直接消息都以以下两种模式之一运行：

    模式 描述
    正常 完整的 IM 功能：实时消息传递、服务器端搜索、机器人参与、斜线命令
    端到端 通过 Signal Protocol 进行端到端加密：服务器是一个不透明的中继，无法读取消息内容，完全排除机器人，并且支持敏感 DM 读取一次/消失的消息

    单个工作区可以并排包含**普通通道和端到端通道，让团队为每个对话选择适当的安全模型。

    关键差异化因素¶

    • 每通道加密模式 — 不是全有或全无；在一个工作空间中混合普通和 E2E
    • 桌面和终端客户端 — Electron GUI 以及面向开发人员、操作员和键盘优先用户的第一阶段 TUI 命令行界面
    • 一流的流媒体消息协议 - 在频道内呈现的逐个令牌的渐进式 AI 响应
    • 6 种语言的 Bot SDK — TypeScript、Java、Python、PHP、Go、Rust
    • 捆绑的基础机器人 - 欢迎、帮助、通知、提醒、投票、Webhooks、开箱即用的荣誉
    • AI Assistant Bot — 在第二阶段使用核心全文搜索进行总结、翻译、起草和搜索； RAG/语义记忆是第三阶段

    3.2 核心设计原则¶

    • 整体优先，边界清晰 — 第 1 阶段作为单个进程部署；代码中的服务边界允许将来拆分而无需重写
    • 零知识加密服务器 — 私钥永远不会离开客户端；信号协议密钥服务器仅存储公钥
    • 流原生协议 — WebSocket 层中的一流 stream_start → stream_chunk → stream_end 事件
    • 机器人 SDK 奇偶校验 — 第一方捆绑机器人使用与第三方开发人员相同的公共 SDK
    • 每个通道混合模式 — 普通通道和 E2E 通道共存于一个工作区中；机器人自动被排除在E2E之外

    5.阶段路线图¶

    完整细分：06 — Phase Roadmap & Milestone Plan

    第一阶段实施任务：参见Implementation Task Documents

    第 1 阶段 — MVP 基础（0-3 个月）¶

    目标：使用混合加密的类似 Slack 的 IM。

    • 电子邮件/密码身份验证、JWT 令牌
    • 工作空间创建、渠道管理（公共/私人/DM）
    • 带有状态机的短信（草稿→已发送→已发送→已读）
    • Markdown 渲染、表情符号反应
    • 用于 1:1 DM 的信号协议 E2E，包括一次读取/消失消息策略
    • 机器人注册、斜杠命令路由、Redis Streams 事件总线
    • 7 个基本机器人：欢迎、帮助、通知、提醒、投票、Webhook、Kudos
    • 带窗口管理、托盘、通知的 Electron shell
    • 用于身份验证、工作区/频道导航、消息传递和 E2E DM 冒烟测试的 TUI 命令行客户端
    • 整体部署：Hono + Socket.IO + Bot Engine 在一个进程中

    第 2 阶段 — 丰富的功能和生产强化（+3–6 个月）¶

    目标：功能完整的 IM 平台已准备好公开发布。

    • 使用 S3 预签名 URL、内联预览、缩略图上传文件/图像
    • 全文消息搜索（PostgreSQL tsvector）
    • 线索回复、线索侧边栏
    • 在线状态、打字指示器、已读回执
    • 通过多成员频道的发件人密钥进行 E2E 组
    • 机器人交互组件（按钮、模态、Block Kit）、webhook 交付
    • AI助手机器人：使用核心全文搜索的/ai ask、/ai summarize、/ai translate、/ai draft、/ai search； RAG 是第 3 阶段
    • 流消息协议：stream_start→stream_chunk→stream_end
    • 另外 7 个基础机器人：Todo、GitHub/GitLab、CI/CD、站立、庆祝、反馈
    • Electron跨平台打包、代码签名、自动更新
    • 离线消息队列、IndexedDB缓存
    • 多实例部署、Redis Sentinel/集群

    第 3 阶段 — 高级和企业（+6–12 个月）¶

    目标：具有语音/视频、多代理人工智能和机器人市场的企业级平台。

    • 语音/视频通话（WebRTC）、屏幕共享
    • SSO (SAML/OIDC)、Google/Microsoft/GitHub OAuth
    • 高级 E2E：安全号码、设备管理、密封发送器、透明度/审计 UX
    • 多设备会话中继
    • 企业管理仪表板、审核日志、数据保留、合规性导出
    • 5 个高级机器人：状态、调度程序、会议记录、AutoMod + 机器人市场
    • 多智能体人工智能：LangGraph Supervisor-Worker、辩论模式、/ai research、/ai code
    • 自托管法学硕士支持（Ollama、vLLM）
    • 微服务拆分：网关/消息/机器人引擎/文件服务
    • NATS JetStream 事件总线，每个服务数据库
    • OpenTelemetry分布式追踪
