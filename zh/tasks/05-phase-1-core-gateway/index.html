    05 — 第 1 阶段 — 核心网关：REST、WebSocket、速率限制和协议¶

    目标¶

    实现核心 Hono + Socket.IO 网关，用于验证客户端、验证协议事件、管理 WebSocket 生命周期以及路由通用 IM 和 Bot 流量。

    范围¶

    • 荣誉 HTTP 服务器。
    • Socket.IO 服务器。
    • 用于 REST 的 JWT 中间件。
    • 用于 WebSocket 握手的 JWT 中间件。
    • 请求/连接日志记录。
    • REST 和 WebSocket 事件的速率限制。
    • 心跳/乒乓球。
    • 房间会员资格：user:{userId}、channel:{channelId}。
    • 通用事件信封。
    • message.send、message.ack、typing.start、typing.stop、presence.update。
    • bot.command.invoke 作为交互事件。

    非目标¶

    • 没有特定于功能的机器人命令解析。
    • 没有民意调查/提醒/荣誉逻辑。
    • 没有人工智能特定的逻辑。
    • 除了转发到附件服务 API 之外，没有原始文件上传处理。

    协议边界¶

    斜杠命令不是普通的消息。它们是交互事件：

    {
  type: 'bot.command.invoke',
  workspaceId: string,
  channelId: string,
  botName: string,
  command: string,
  args: string[],
  triggerId?: string
}

    网关可以在接受后创建审核/系统消息，但默认情况下不得将命令保留为用户文本消息。

    端到端规则¶

    • 不要信任客户端提供的 encryption 标志。
    • 从数据库解析通道模式。
    • 如果通道模式为e2e，则跳过机器人调度并将有效负载视为不透明密文。
    • 拒绝端到端渠道中的机器人命令。

    验收标准¶

    • REST 服务器启动并公开运行状况端点。
    • WebSocket 连接使用 JWT 进行身份验证。
    • 客户端授权后加入用户房间和频道房间。
    • 无效的事件有效负载会因键入错误而被拒绝。
    • WebSocket 速率限制适用于每个用户/连接。
    • bot.command.invoke 仅针对普通通道路由至 Bot Engine。
    • E2E 通道从不发出机器人事件。

    测试计划¶

    • 使用有效/无效 JWT 的 WebSocket 握手。
    • 消息在正常通道中发送。
    • E2E 通道中发送的消息绕过机器人事件。
    • 正常通道中的机器人命令成功。
    • E2E 通道中的 Bot 命令失败并显示 e2e_bots_disabled。
    • 消息泛滥​​的速率限制测试。
