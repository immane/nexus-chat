    03 — 第 1 阶段 — 数据库架构、迁移和持久性边界¶

    目标¶

    使用 Drizzle ORM 实施第一阶段 PostgreSQL 模式，同时保留核心 IM 数据、附件生命周期、机器人基础设施和机器人拥有的功能数据之间的严格界限。

    范围¶

    • 将 Drizzle ORM 添加到 apps/server。
    • 创建迁移管道。
    • 实施核心表。
    • 实施附件表。
    • 实施机器人安装/订阅表。
    • 实施信号键表。
    • 实施审计日志表。
    • 添加种子数据以供本地开发。

    非目标¶

    • 没有民意调查/提醒/荣誉/待办事项表。
    • 第一阶段没有人工智能嵌入表。
    • 每个服务没有数据库。
    • 没有 Elasticsearch 或矢量数据库。

    核心表¶

    表 业主 目的
    users 核心认证 用户身份
    workspaces 核心工作区 租户/工作区根目录
    workspace_members 核心工作区 工作区 RBAC
    channels 核心频道 公共/私人/DM 渠道，正常/e2e 模式
    channel_members 核心频道 会员资格和读取光标
    messages 核心讯息 消息记录和渲染有效负载
    message_reactions 核心讯息 表情符号反应
    files 核心附件 文件元数据、扫描状态、对象密钥、保留
    upload_sessions 核心附件 预定义上传会话生命周期
    message_attachments 核心附件 消息到文件关联
    bot_integrations 核心机器人基础设施 机器人身份、令牌哈希、范围
    bot_channel_memberships 核心机器人基础设施 哪些机器人安装在哪些渠道
    bot_event_subscriptions 核心机器人基础设施 每个机器人接收哪些事件
    signal_prekey_bundles 核心信号 公共身份密钥+签名的预密钥元数据
    signal_one_time_prekeys 核心信号 一次性预密钥
    signal_sessions 核心信号 为以后多设备中继预留
    audit_logs 核心审计 仅附加关键操作日志

    边界规则¶

    • 核心架构不得包含产品工作流程表，例如 polls、reminders、kudos、todos 或 standups。
    • 机器人通过机器人拥有的表或范围 KV 存储来存储工作流程状态。
    • 核心附件服务拥有文件生命周期和安全状态。
    • @FileBot 可以存储工作流程设置和文件 ID 引用，但不存储对象密钥或扫描权限。

    重要限制¶

    • 对消息使用 UUID v7 或单调 ID 策略。
    • clientMsgId 对于每个发件人来说必须是唯一的，而不是全局的。
    • 如果不可为空，senderId 和 createdBy 应使用 onDelete: restrict。
    • 端到端消息仅存储密文。
    • E2E 文件仅存储不透明的加密 blob。

    指标要求¶

    使用案例 索引
    频道分页 (channel_id, id DESC)
    幂等发送 (sender_id, client_msg_id)独特
    用户频道列表 (user_id, joined_at)
    工作区通道名称 (workspace_id, name) 在适用的情况下是唯一的
    机器人频道查找 (channel_id) 于 bot_channel_memberships
    文件工作区列表 (workspace_id, created_at)
    文件扫描队列 (scan_status)
    上传会话清理 (status, expires_at)

    迁移命令¶

    pnpm --filter @nexus-chat/server db:generate
pnpm --filter @nexus-chat/server db:migrate
pnpm --filter @nexus-chat/server db:studio

    验收标准¶

    • 新数据库从空状态迁移。
    • drizzle-kit 可以生成并应用迁移。
    • 种子脚本创建 1 个工作区、2 个用户、1 个普通频道、1 个 DM。
    • 核心迁移中不存在特定于工作流的机器人表。
    • 附件表存在且不属于 FileBot。
    • 机器人成员资格/订阅表存在。

    测试计划¶

    • 从空数据库向上迁移。
    • 如果支持，则在本地环境中进行迁移回滚。
    • 插入种子数据。
    • 验证频道分页查询使用索引。
    • 验证重复的(sender_id, client_msg_id)被拒绝。
    • 如果数据库检查或服务不变式到位，则验证机器人无法插入 E2E 通道。
