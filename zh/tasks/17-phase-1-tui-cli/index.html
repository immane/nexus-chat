    17 — 第 1 阶段 — TUI 命令行客户端¶

    目标¶

    提供键盘优先的终端客户端，该客户端执行与桌面客户端相同的公共 API 和 WebSocket 合约，从而实现快速的开发人员工作流程、可操作的冒烟测试以及非 GUI 环境的基本使用。

    范围¶

    • 创建 apps/tui 作为 Node.js 包，使用 Ink 进行终端渲染，使用 Commander 进行命令解析。
    • 通过操作系统钥匙串（如果可用）实现登录/注销、令牌持久性，以及仅用于本地开发的 .env 后备。
    • 列出经过身份验证的用户可用的工作区、频道和 1:1 DM。
    • 打开通道或 DM 并呈现带有消息状态、发件人、时间戳和 E2E 模式徽章的回滚窗口。
    • 通过与 Web/桌面客户端相同的 WebSocket message.send 合约发送正常模式文本消息。
    • 通过packages/signal发送和接收阶段1 E2E DM消息，包括一次读取/消失消息冒烟测试。
    • 调用斜杠命令并在正常通道中呈现机器人回复。
    • 为 CI 冒烟测试提供非交互式命令：login、send、read、e2e-smoke 和 bot-smoke。

    非目标¶

    • 与 Electron 客户端没有完全的视觉效果。
    • 没有文件上传/下载用户界面。
    • 没有插件 UI 界面或机器人交互组件。
    • 除了第一阶段单设备密钥模型之外，没有多设备 E2E 支持。
    • 除了 stdout/stderr 和退出代码之外，没有终端通知。

    建议的命令¶

    pnpm --filter @nexus-chat/tui dev
nexus login --server http://localhost:3000 --email user@example.com
nexus workspaces
nexus channels --workspace <workspace-id>
nexus chat <channel-or-dm-id>
nexus send <channel-or-dm-id> "hello"
nexus e2e-smoke --to <user-id> --read-once "secret"
nexus bot-smoke --channel <channel-id> "/help"

    验收标准¶

    • TUI 登录本地第一阶段服务器成功。
    • 用户可以列出工作区/频道并打开频道或 DM。
    • 用户可以发送和接收普通短信。
    • 用户可以建立E2E DM会话并交换加密消息。
    • nexus e2e-smoke --read-once 验证接收者是否可以读取一次，并且后续的提取仅返回逻辑删除/过期状态。
    • Slash命令冒烟测试可以在正常通道中调用参考机器人。
    • 命令返回 CI 使用的确定性退出代码。

    测试计划¶

    • 命令解析和配置解析的单元测试。
    • 针对本地服务器的身份验证和工作区/频道列表的集成测试。
    • 用于正常消息发送/接收的 WebSocket 冒烟测试。
    • 针对加密 DM 和一次读取过期的 E2E 冒烟测试。
    • 使用参考帮助机器人进行机器人命令冒烟测试。
