    01 — 第 1 阶段 — 项目支架和开发人员工作流程¶

    目标¶

    创建所有第 1 阶段工作所依赖的 monorepo 基础：包布局、TypeScript 配置、格式化、linting、测试、本地开发脚本和 CI 约定。

    所有权¶

    面积 业主
    Monorepo 工具 平台团队
    TypeScript / lint / 测试基线 平台团队
    CI 工作流程 平台团队

    范围¶

    • 初始化pnpm工作区。
    • 配置 Turborepo 任务管道。
    • 创建初始包/应用程序目录。
    • 添加共享 TypeScript 配置。
    • 添加 ESLint 和 Prettier。
    • 添加 Vitest 基线。
    • 添加dotenv约定和.env.example。
    • 添加构建/测试/lint/typecheck/dev 的根脚本。

    非目标¶

    • 没有应用程序功能。
    • 除了空迁移文件夹之外没有数据库架构。
    • 没有生产部署管道。
    • 还没有 Electron 封装。

    目标结构¶

    nexus-chat/
├── apps/
│   ├── server/
│   ├── web/
│   ├── desktop/

├── packages/

└── vitest.config.ts

    可交付成果¶

    可交付成果 描述
    package.json 根脚本和工作区元数据
    pnpm-workspace.yaml 工作空间包 glob
    turbo.json build、dev、lint、typecheck、test 管道
    tsconfig.base.json 严格的共享 TypeScript 设置
    apps/*/package.json 带有占位符脚本的空应用程序包
    packages/*/package.json 带有构建/类型检查脚本的清空共享包
    .env.example 记录的本地环境变量

    所需的根脚本¶

    {
  "scripts": {
    "dev": "turbo dev",
    "build": "turbo build",
    "test": "turbo test",
    "lint": "turbo lint",
    "typecheck": "turbo typecheck",
    "format": "prettier --write .",
    "format:check": "prettier --check ."
  }
}

    TypeScript 规则¶

    • strict: true
    • noUncheckedIndexedAccess: true
    • exactOptionalPropertyTypes: true
    • noImplicitOverride: true
    • moduleResolution: "Bundler" 用于前端/共享包。
    • 如果需要，moduleResolution: "NodeNext" 用于服务器/桌面包。

    验收标准¶

    • pnpm install 成功。
    • pnpm typecheck 使用占位符包成功。
    • pnpm lint 成功。
    • pnpm test 成功。
    • 对于占位符包，pnpm build 成功或完全无操作。
    • 新包可以使用工作区协议从 @nexus-chat/shared 导入。

    测试计划¶

    • 运行pnpm install。
    • 运行pnpm lint。
    • 运行pnpm typecheck。
    • 运行pnpm test。
    • 运行pnpm build。

    依赖关系¶

    没有。这是所有其他第一阶段任务的根本先决条件。
