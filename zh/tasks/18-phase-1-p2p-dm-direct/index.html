    18 — 第 1 阶段 — 1:1 E2EE DM 的 P2P 直接连接¶

    目标¶

    为 1:1 E2EE DM 添加机会性 WebRTC 数据通道直接连接。当 P2P 路径成功时，消息将完全绕过服务器。当它失败（NAT/防火墙）时，系统会透明地回退到现有的服务器中继的 WebSocket 路径。

    范围¶

    • 用于 1:1 E2EE DM 消息传输的 WebRTC 数据通道。
    • 基于服务器的信令中继，用于 SDP 提供/应答和 ICE 候选交换。
    • P2pConnectionPool 用于管理 WebRTC 对等连接。
    • HybridTransport 发送/接收抽象：首先尝试 P2P，然后回退到中继。
    • P2P 消息帧（通过数据通道的 JSON），使用 clientMsgId 进行重复数据删除。
    • 通过数据通道的 P2P 确认，具有用于多设备同步的轻量级服务器确认。
    • 连接拆卸+清理（挂断信号、池删除）。
    • P2P 尝试失败后的冷却计时器（30 秒），以避免重复失败。
    • 每个对等连接缓存（重用已建立的连接）。
    • ICE 候选人不断涌现。
    • 所有 P2P 信令事件的新共享模式。
    • WebSocket 网关中的服务器端 P2P 事件中继。
    • 单元测试、集成测试和 p2p-smoke TUI 命令。
    • 通过环境变量（STUN/TURN）配置ICE服务器。

    非目标¶

    • 无群组通道 P2P（信号发送器密钥/MLS 是一个单独的问题）。
    • 此任务中没有 TURN 服务器配置（仅文档配置）。
    • 正常模式（非 E2EE）通道没有 P2P — 服务器中继适用于此。
    • 没有 TUI 或 CLI P2P 支持（Node.js 缺乏本机 WebRTC；wrtc 包存在维护问题）。
    • 没有 P2P 状态指示器的 UI（绿色/黄色/灰色锁图标）——推迟到 UI 润色任务。
    • 没有超出deviceId意识的多设备P2P协调。
    • 没有通过 P2P 的文件传输（附件仍然通过服务器）。

    18.6 混合交通¶

    新文件：apps/web/src/lib/p2p/transport.ts

    • [ ] 18.6.1 实现HybridTransport类：
    • constructor(session: SignalSession, pool: P2pConnectionPool, wsSend, signalingSend)。
    • async sendMessage(input: SendMessageInput): Promise<SendResult>：
      1. 拨打encryptForSession(session, plaintext)。
      2. 勾选pool.has(targetUserId)→通过数据通道P2P发送。
      3. 如果没有连接且未处于冷却时间 → 启动 WebRTC，超时时间为 5 秒。
      4. 如果连接成功→P2P发送。
      5. 如果超时/失败 → 服务器 WebSocket 中继回退。
    • onMessage(handler)：同时监听数据通道和WebSocket；通过 clientMsgId 进行重复数据删除；解密并交付。
    • destroy()：关闭池并删除侦听器。
    • [ ] 18.6.2 实施sendP2pFrame(dataChannel, frame)和sendP2pAck(dataChannel, clientMsgId)。
    • [ ] 18.6.3 实现客户端clientMsgId dedup（最后1000的LRU集）。
    • [ ] 18.6.4 实施后备：sendViaRelay(wsSend, input) → 现有的 socket.emit 流。
    • [ ] 18.6.5 编写单元测试：
    • P2P 可用：消息通过数据通道传输，返回{ path: "p2p" }。
    • P2P 不可用：退回到中继，返回{ path: "relay" }。
    • 冷却激活：跳过 P2P 尝试，直接进入中继。
    • Dedup：两个路径上的 clientMsgId 相同，仅处理第一个路径。
    • 多条消息：全部通过相同的缓存数据通道。
    • 数据通道关闭：下一条消息回退到中继。
    • [ ] 18.6.6 运行pnpm --filter @nexus-chat/web typecheck && pnpm --filter @nexus-chat/web test。

    验收标准¶

    • [ ] 两个Web客户端可以建立WebRTC数据通道并直接发送E2EE密文消息，无需服务器数据路径参与。
    • [ ] SDP Offer/answer 和 ICE 候选者通过服务器 WebSocket 信令路径成功中继。
    • [ ] 如果 WebRTC 失败（模拟：阻止 STUN），则消息将通过现有服务器 WebSocket 中继路径传递，不会出现用户可见的错误。
    • [ ] clientMsgId 重复数据删除有效：到达 P2P 和中继路径的消息仅被处理一次。
    • [ ] 所有 P2P 模式均由 Zod 在客户端和服务器边界进行验证。
    • [ ] 服务器网关仅将 P2P 事件中继给经过身份验证的目标用户；未知的目标被悄然丢弃。
    • [ ] 连接池正确管理生命周期：每个对等点的创建、重用、拆卸。
    • [ ] 冷却计时器可防止 30 秒内重复失败的 WebRTC 尝试。
    • TUI 中的 [ ] p2p-smoke 命令验证模式和服务器信令接受情况。
    • [ ] 所有现有测试（72 个测试）将继续通过，无需修改。
    • [ ] 未添加新的 npm 运行时依赖项（WebRTC 是浏览器原生的）。
    • [ ] ESLint、TypeScript 严格模式、Vitest 单元测试和 Vitest 覆盖率全部通过。
